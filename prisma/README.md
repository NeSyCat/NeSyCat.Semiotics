# Prisma 8 ("Prisma Next") — schema source of truth

`contract.prisma` is the SOT for the schema (tables, columns, RLS, policies).
It replaces `_concept/03-orm-schema/schema.ts` (Drizzle) as the thing you edit
to change the data model — see `.foreman/scratch/design-prisma8-v3.md` for the
adoption spike this project is based on. `contract.json`/`contract.d.ts` are
generated by `contract emit`, committed (the runtime imports `contract.json`),
and must never be hand-edited.

Evolution: edit `contract.prisma`, run `npm run p8:emit`, then `npm run
p8:update:dry` to preview the delta against a live DB and `npm run p8:update`
to apply it (this project uses `db update`, not the migration-graph commands —
`migration plan`/`migrate` broke post-adoption in the spike; see the design
doc's PROVEN MECHANICS block).

`sql/` is a lane the contract cannot see: functions and triggers are not PSL
concepts, so `01-functions.sql` (3 `SECURITY DEFINER` RLS helpers the policies
call by name) and `02-guards.sql` (the orphan-organization trigger) live here
as hand-written, idempotent SQL, applied by CI via `psql`. `db verify
--strict` will never flag them missing — they are permanently outside the
contract's view.

Fresh-DB bootstrap order (preview branches): `psql 01-functions.sql` (policies
below reference these functions — `db init` fails without them) → `prisma db
init` (builds tables/RLS/policies from the contract and signs the DB) → `psql
02-guards.sql`.

Prod adoption: done by `contract infer --db` + `db sign` — zero migrations
executed against prod. See the design doc for the full runbook.

Pinned versions: `prisma@8.0.0-rc.5` (unified CLI), `@prisma/orm-postgres@8.0.0-rc.3`, `pg@8.23.0`.
